## What is BuildBox?

BuildBox provides a visual route to game creation for people who do not want every part of development to depend on handwritten code. Its workspace combines drag-and-drop editing, visual scripting, and project organization features, helping individual creators and teams turn concepts into playable builds.

The tool is intended for both desktop and web workflows. Projects can be prepared for multiple platforms, including HTML5, while development remains focused on arranging assets, defining behavior, and managing project structure. This supports rapid prototyping, repeated previews, and packaging for different targets.

## Typical workflow

BuildBox is organized around a simple development loop: prepare resources, define behavior, preview the game, and export the completed project.

1. Create a new project or open an existing one.
2. Use the visual editor to add scenes, objects, and assets.
3. Connect gameplay behavior with visual scripting.
4. Preview changes throughout development.
5. Run live multiplayer tests when interactive validation is needed.
6. Export for the intended target, including HTML5 when applicable.

Before a final export, organize the project assets and inspect its dependency graphs. Doing so can help avoid cleanup work at the end of the build process.

## Project configuration

Configuration is generally kept within the project environment instead of one universal global configuration file. Depending on the setup, review the project workspace, export controls, and local application preferences for the relevant settings.

A representative configuration can look like this:

    {
      "projectName": "MyGame",
      "platform": "html5",
      "multiplatformExport": true,
      "visualScripting": true,
      "language": "en"
    }

When a repository uses another directory structure, place project-level options near the assets and build files that use them.
